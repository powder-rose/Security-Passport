# Каталог постановлений

Страница `/postanovleniya/` объединяет опубликованные коммерческие направления. Карточки образуют один список; номер постановления не задаёт порядок. Страница использует общие шапку, контейнер, FAQ, форму обращения и футер сайта.

## Управление через CMS

Откройте «Каталог постановлений» по адресу `/admin/directions`. Выберите карточку слева, измените название, номер ПП, краткое описание, URL или порядок и нажмите «Сохранить каталог». Число в поле порядка задаёт позицию в каталоге: меньшее число располагается выше.

Переключатели «Показывать в каталоге» и «Показывать в основном меню» независимы. Новая карточка создаётся с обоими выключенными переключателями. Существующие названия и порядок пунктов меню сохранены; добавленную карточку можно отдельно включить в меню. Направление не добавляется в меню автоматически при создании коммерческой страницы.

Для добавления направления сначала опубликуйте коммерческую страницу, затем добавьте карточку. Подсказки URL берутся из опубликованной сборки. Номер постановления, его действие, область применения и соответствие страницы этому режиму проверяет редактор до включения карточки. CMS проверяет техническую доступность страницы, но не заменяет нормативную проверку.

Полный адрес основного домена принимается и приводится к внутреннему каноническому пути. Внешние адреса, ссылки на блог, якоря, параметры URL, дубли адресов, незаполненные поля и видимые карточки без опубликованной коммерческой страницы блокируются. Если страницу удалили из сборки, закрыли `noindex` либо изменили её canonical на другой адрес, карточка и пункт меню скрываются при чтении публичных данных. Сохранить такую карточку можно с двумя выключенными переключателями либо с исправленным URL.

Раздел «Тексты страницы и SEO» редактирует Title, Description, H1, вступление, пояснение об области применения, общий заголовок и введение каталога, информационный блок, FAQ и финальный CTA. Поля содержат обычный текст; абзацы разделяются пустой строкой. HTML-конструктор не используется.

Сохранение сохраняет весь документ с проверкой его ревизии. Устаревшее окно не может перезаписать более позднее сохранение. При ошибке текущие правки остаются в форме; при конфликте сохраните нужный текст отдельно и обновите страницу.

## Первоначальный состав

В каталоге включены 14 карточек существующих страниц. Торговые объекты и розничные рынки, а также два режима № 272 представлены раздельно. Для образовательной карточки указан № 1006; отдельной страницы высшего образования и науки по № 1421 пока нет. Детские лагеря по № 732 и дополнительные ведомственные направления добавляются после появления отдельных опубликованных страниц.

Общая страница ТЭК остаётся в прежнем меню, но в исходном каталоге скрыта: техническое задание требует отдельные опубликованные страницы конкретных режимов. Во вступлении не указано, что детские лагеря уже включены в текущий перечень.

## Хранение и отображение

Настройки и карточки хранятся в `data/directions.json`. Переменная `CATALOG_FILE` позволяет задать другой путь; относительный путь разрешается от `PASSPORT_PROJECT_ROOT`. В production это постоянный рабочий каталог, а не каталог отдельного релиза. Файл нужно включать в резервное копирование данных. При отсутствии файла используются исходные значения `shared/catalog/defaults.js`; добавление новой карточки через CMS не требует редактировать этот файл.

Каталог рендерится на сервере из текущих данных CMS. Все карточки и ссылки входят в HTML ответа; сохранение не требует новой сборки для применения текста или видимости. Меню получает актуальную компактную проекцию из `/api/directions/menu` после загрузки страницы. Во время полного prerender текущие пункты меню включаются также в HTML и данные гидратации всех страниц. При недоступности API сохраняется навигация из последней сборки.

Каталог входит в оба sitemap. Дополнительные страницы поиска, фильтров, сортировки и пагинации не создаются. Наличие параметров запроса даёт `X-Robots-Tag: noindex, follow`; canonical остаётся `/postanovleniya/`.

Для серверного рендера используются SSR-модуль и raw template текущего неизменяемого runtime. При локальной разработке — последние результаты полной сборки в `dist/server` и `dist/template`. Перед локальной проверкой выполните `npm run build`, затем запустите backend через `npm run dev:api` с `NODE_ENV=development`. Админка: `http://localhost:8787/admin/directions`; каталог: `http://localhost:8787/postanovleniya/`. После изменения кода нужна новая полная сборка, изменения данных CMS применяются сразу.

Кнопки каталога ведут к общей форме `#contact`. Запрос использует существующий `/api/leads`, общую валидацию и источник «Каталог постановлений». Отдельный обработчик заявок не добавлен.

## Будущая активация на сервере

Для первого запуска требуется полный deploy с новым frontend и backend. В Nginx необходимы два точных location для `/postanovleniya` и `/postanovleniya/` из `deploy/nginx/pasport-bezopasnosty.ru.conf`: адрес без завершающего слеша перенаправляется, каталог со слешем проксируется в backend. Статическая выдача файла каталога через общий `try_files` не отражает сохранения CMS сразу и не должна подменять этот маршрут.

Перед активацией проверьте HTML `/postanovleniya/` непосредственно на backend, затем `nginx -t`, и только после успешной проверки применяйте конфигурацию. Этот пакет не выполняет деплой, изменение Nginx или перезапуск production. Активация отложена до утверждения.

## Проверки

`npm run test:server` включает `tests/server/catalog.test.mjs`: сохранение и восстановление данных, независимая видимость, создание карточки, проверка опубликованных страниц, дубли, некорректные входные данные, конфликт ревизий, авторизация, маршруты и источник заявки.

После `npm run build:artifacts` выполните `npm run test:e2e:run -- tests/e2e/regulations-catalog.spec.js`. Проверяются HTML без JavaScript, существующие ссылки, адаптивность, меню, FAQ, общая форма, редактирование CMS и блокировка дублей.
